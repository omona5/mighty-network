# 마이티 튜토리얼 기획안

## 1. 목적

처음 접하는 플레이어가 한 판을 끝까지 진행하면서 이 게임의 핵심 흐름과 필수 규칙을 익히게 한다.

현재 게임은 5인용 마이티이며, 서버가 규칙과 승패를 판정한다. 튜토리얼도 별도 규칙을 새로 만들기보다 **현재 서버 규칙을 그대로 사용**하고, 싱글플레이의 봇 4명과 고정된 패/행동을 이용해 안전하게 안내한다.

### 학습 완료 기준

플레이어가 아래를 스스로 할 수 있으면 완료로 본다.

1. 타이틀에서 싱글플레이 또는 멀티플레이를 시작할 수 있다.
2. 입찰에서 공약, 기루다, 노기루, 패스의 의미를 안다.
3. 주공이 되었을 때 바닥패 3장을 받고 3장을 버린다.
4. 카드 프렌드와 노프렌드의 차이를 안다.
5. 리드 무늬 따라내기, 기루다, 마이티, 조커, 조커콜의 우선순위를 이해한다.
6. 주공팀 목표 점수와 결과/누적 점수를 읽는다.

## 2. 현재 게임 기준

| 항목 | 현재 구현 기준 | 튜토리얼에서 다룰 방식 |
| --- | --- | --- |
| 인원/카드 | 5명, 각 10장 + 바닥패 3장 | 플레이어 1명 + 봇 4명, 고정 배분 |
| 입찰 | 최소 공약부터 순차 입찰, 더 높은 공약만 가능, 패스 후 재입찰 불가 | 첫 공약은 정답 선택을 유도하고, 봇은 정해진 반응 |
| 전원 패스 | 최소 공약을 낮춰 재입찰하고, 최저 공약도 전원 패스면 재배분 | 별도 안내 카드로 간단히 소개만 하고 기본 과정에서는 발생시키지 않음 |
| 바닥패 | 주공이 3장을 받아 13장에서 3장을 버림; 버린 점수 카드는 주공팀 점수 | 실제 카드 선택 과제로 사용 |
| 프렌드 | 카드 프렌드(소유자는 카드가 나올 때 공개), 플레이어 프렌드(즉시 공개), 노프렌드 | 카드 프렌드를 실제로 선택하고 공개 순간을 보여 줌; 나머지는 보조 설명 |
| 기본 트릭 | 리드 무늬가 있으면 따라내기, 없으면 다른 카드 가능 | 유효 카드만 강조하고 잘못된 카드는 이유와 함께 비활성화 |
| 강한 카드 | 마이티 > 조커(첫/마지막 트릭 및 조커콜 예외) > 기루다 > 리드 무늬 | 각각 최소 1회씩 고정 상황으로 체험 |
| 조커 리드 | 낼 무늬를 선언 | 조커를 리드하고 무늬를 고르는 과제로 제공 |
| 조커콜 | 조커콜 카드 리드 시 발동 여부 선택; 발동하면 조커 보유자는 조커 또는 마이티를 내야 함 | 발동 선택과 강제 제출 결과를 한 단계에 묶어 보여 줌 |
| 점수/정산 | A, K, Q, J, 10은 각 1점; 목표 달성 시 주공팀 승리 | 마지막에 점수 카드와 목표 점수를 연결해 설명 |

> 마이티는 기루다가 스페이드이면 다이아 A, 그 외/노기루이면 스페이드 A다. 조커콜은 기루다가 클로버이면 스페이드 3, 그 외에는 클로버 3이다. 이 값은 게임 HUD에도 표시된다.

## 3. 권장 진입 구조

타이틀의 `튜토리얼 (준비 중)` 버튼을 `튜토리얼`로 변경하고, 누르면 일반 멀티플레이 방이 아닌 **로컬 튜토리얼 세션**을 시작한다.

```text
타이틀
  ├─ 싱글플레이: 일반 봇 게임
  ├─ 멀티플레이: 방 생성/입장
  └─ 튜토리얼: 고정 시나리오 1회
       ├─ 기본 진행 (필수)
       ├─ 특수 규칙 연습 (필수)
       └─ 결과/다시 보기
```

권장 방식은 `TutorialController`가 현재 게임 화면 위에 안내 오버레이를 띄우고, 각 단계에서 허용할 입력만 열어 주는 형태다. 카드 유효성·트릭 승패·점수는 기존 서버 `RuleEngine`과 `Scoring` 결과를 계속 신뢰한다.

## 4. 튜토리얼 시나리오

총 8~12분, 11단계로 구성한다. 메시지는 짧게, 설명보다 선택 행동을 먼저 둔다. 각 단계에는 `건너뛰기`와 `다시 설명`을 제공하되, 필수 행동을 건너뛴 경우에는 해당 개념을 결과 요약에서 다시 보여 준다.

| 단계 | 화면/상황 | 플레이어 행동 | 안내 핵심 | 완료 조건 |
| --- | --- | --- | --- | --- |
| 0. 환영 | 테이블 전체를 어둡게 하고 손패/중앙/좌상단 규칙 HUD/좌석을 순서대로 강조 | `시작` | 내 손패, 중앙 트릭, 현재 차례, 규칙 HUD의 위치 | 시작 클릭 |
| 1. 입찰 | 플레이어 차례, 예시 손패 제공 | `13점 + 하트` 공약 제출 | 공약은 주공팀이 얻겠다고 약속하는 점수, 기루다는 강한 무늬 | 올바른 공약 제출 |
| 2. 패스 | 봇이 공약을 올린 뒤 플레이어 차례 | 패스 | 더 높게 부르거나 패스할 수 있으며, 패스하면 이번 입찰에 복귀 불가 | 패스 클릭 |
| 3. 주공 확정 | 봇이 패스해 플레이어가 주공이 된 상황 | `계속` | 주공·목표 점수·기루다와 마이티/조커콜 카드가 HUD에 확정됨 | 확인 |
| 4. 바닥패 | 바닥패 3장이 플레이어 손패로 이동 | 낮은 비점수 카드 3장 선택 후 버리기 | 13장 중 3장을 버리며, 버린 점수 카드는 주공팀 점수에 포함 | 정확히 3장 버림 |
| 5. 프렌드 | 프렌드 선택 UI | 미리 정한 카드 프렌드 선택 | 카드 프렌드의 소유자는 그 카드가 나올 때까지 비공개 | 지정 완료 |
| 6. 따라내기 | 봇이 하트를 리드, 플레이어는 하트를 가진 상태 | 하트 카드 1장 제출 | 리드 무늬가 손에 있으면 반드시 따라낸다. 마이티/조커는 예외 | 유효 카드 제출 |
| 7. 기루다와 마이티 | 하트 리드 트릭에서 다른 봇이 기루다를 냄, 다음 고정 트릭에서 플레이어가 마이티를 냄 | 마이티 제출 | 기루다는 리드 무늬보다 강하지만 마이티는 항상 최강 | 트릭 승자 표시 확인 |
| 8. 조커 리드 | 플레이어가 조커를 리드할 수 있는 고정 턴 | 조커 후 무늬 선택 | 조커 리드에는 따라낼 무늬 선언이 필요 | 무늬 선택 후 트릭 종료 |
| 9. 조커콜 | 조커콜 카드 리드 가능, 다른 봇이 조커 보유 | `조커콜 사용` 선택 | 조커콜 발동 시 조커 보유자는 조커를 내야 하며 마이티는 방어 예외 | 강제 제출/승자 확인 |
| 10. 프렌드 공개·점수 | 카드 프렌드가 테이블에 제출되고, 남은 트릭은 빠르게 자동 진행 | `결과 보기` | 프렌드 공개, 점수 카드, 목표까지 남은 점수의 관계 | 프렌드 공개 확인 |
| 11. 결과 | 기존 결과 화면 확장 | `완료` 또는 `다시 연습` | 주공팀/수비팀 점수, 공약 달성 여부, 누적 정산 | 버튼 선택 |

### 고정 패 설계 원칙

- 실제 53장 구성과 각 플레이어 10장, 바닥패 3장 규칙을 유지한다.
- 시작 플레이어가 13점 하트 공약을 낼 수 있는 강한 하트 계열 손패를 준다.
- 바닥패 선택에서는 낮은 비점수 카드 3장과 보존해야 할 카드(점수 카드, 기루다, 마이티/조커)를 명확히 섞어 둔다.
- 단계 6은 리드 무늬 카드가 최소 2장 있어 선택은 가능하지만, 다른 무늬는 비활성화한다.
- 단계 7~9에서 필요한 마이티, 조커, 조커콜과 프렌드 카드는 반드시 의도한 플레이어에게 배분한다.
- 연습 목적상 남은 트릭은 봇 자동 진행으로 단축하되, 최종 점수는 실제 `Scoring`으로 계산한다.

## 5. 화면·카피 가이드

### 안내 오버레이

- 강조 대상 외 영역은 반투명 딤 처리한다.
- 말풍선에는 한 번에 한 개의 규칙만 넣고, 2문장 이내로 제한한다.
- 강조 대상 옆에 `1 / 11` 같은 진행 표기를 둔다.
- 모바일 세로 화면에서는 말풍선이 손패나 선택 버튼을 가리지 않도록 상단 또는 중앙 빈 공간으로 자동 배치한다.

### 예시 카피

| 상황 | 권장 문구 |
| --- | --- |
| 입찰 | `이번 판에 주공팀이 얻을 점수와 기루다를 약속하세요. 이 손패라면 13점 하트가 좋은 시작입니다.` |
| 바닥패 | `바닥패를 받아 13장이 되었습니다. 약한 카드 3장을 버리세요. 버린 점수 카드는 우리 팀 점수에 들어갑니다.` |
| 따라내기 | `하트가 리드되었습니다. 손에 하트가 있으므로 하트를 내야 합니다.` |
| 마이티 | `마이티는 언제나 가장 강합니다. 기루다보다도 이깁니다.` |
| 조커콜 | `조커콜을 사용하면 조커를 끌어낼 수 있습니다. 조커 보유자는 조커 또는 마이티를 내야 합니다.` |
| 결과 | `공약은 13점, 주공팀은 15점을 얻었습니다. 공약 성공!` |

## 6. 구현 범위와 순서

### 1차: 플레이 가능한 핵심 튜토리얼

1. `TutorialController` 및 `TutorialStep` 상태 모델을 추가한다.
2. 타이틀의 튜토리얼 버튼을 연결하고 튜토리얼 세션 진입 플래그를 만든다.
3. 튜토리얼 전용 고정 덱/봇 행동 스크립트를 만든다.
4. 기존 게임 단계(`bidding → exchanging_kitty → choosing_friend → playing → finished`)를 재사용한다.
5. 카드 클릭, 입찰, 바닥패, 프렌드 선택 UI에 단계별 입력 제한과 하이라이트를 추가한다.
6. 오버레이, 다시 설명, 건너뛰기, 완료 화면을 만든다.

### 2차: 이해도 보강

1. 트릭 종료마다 `왜 이 카드가 이겼는지` 한 줄 설명을 띄운다.
2. 결과 화면에 배운 규칙 체크리스트를 표시한다.
3. 조커/조커콜만 다시 해 볼 수 있는 짧은 특수 규칙 연습을 추가한다.
4. 완료 여부를 로컬 저장해 타이틀 버튼에 `완료` 배지를 표시한다.

### 권장 책임 분리

| 구성 요소 | 책임 |
| --- | --- |
| 서버/튜토리얼 시나리오 | 고정 덱, 봇의 예정 행동, 실제 룰 판정과 점수 계산 |
| `TutorialController` | 현재 단계, 진행 조건, 건너뛰기/재시작, 이벤트 구독 |
| UI 오버레이 | 강조 영역, 안내 문구, 다음/다시 설명 버튼 |
| 기존 `NetworkManager` | 방 상태 표시, 카드/입찰/프렌드 입력, 결과 화면 |
| 기존 `RuleEngine`, `Scoring` | 카드 합법성, 트릭 승자, 점수/승패의 단일 기준 |

## 7. 예외 처리와 UX 원칙

- 잘못된 카드는 서버 오류를 기다리지 않고 회색 처리한다. 탭했을 때는 `하트가 있으므로 하트를 내야 합니다`처럼 이유를 표시한다.
- 플레이어가 의도한 정답과 다른 유효 카드를 내더라도, 학습 목표를 깨지 않는다면 막지 않는다. 대신 결과 설명을 그 선택에 맞춰 바꾼다.
- 고정 시나리오를 벗어나는 선택이 다음 특수 규칙 장면을 불가능하게 만들면, 해당 단계에서만 선택지를 제한한다.
- 연결이 끊겨도 튜토리얼은 로컬/싱글플레이 기준으로 즉시 재개하거나 처음부터 다시 시작할 수 있어야 한다.
- 멀티플레이 방에서는 튜토리얼 오버레이를 표시하지 않는다. 다른 플레이어의 진행을 막지 않기 위함이다.

## 8. 검수 체크리스트

- [ ] 튜토리얼 버튼이 타이틀에서 활성화되고 일반 싱글/멀티 경로와 분리된다.
- [ ] 5인·10장·바닥패 3장이라는 실제 게임 구성이 유지된다.
- [ ] 입찰, 바닥패, 프렌드, 따라내기, 마이티, 조커, 조커콜, 결과가 순서대로 실제 행동으로 진행된다.
- [ ] 튜토리얼의 카드 유효성/승자/점수가 일반 게임과 같은 서버 규칙 결과를 낸다.
- [ ] 카드 프렌드의 소유자 이름이 카드가 나오기 전에는 노출되지 않는다.
- [ ] 첫/마지막 트릭의 조커 예외를 튜토리얼에서 잘못 가르치지 않는다.
- [ ] 가로/세로 화면에서 안내가 손패·입력 버튼을 가리지 않는다.
- [ ] 건너뛰기, 재시작, 결과 후 타이틀 복귀가 가능하다.

## 9. 결정이 필요한 항목

구현 전에 아래 두 가지만 확정하면 시나리오의 난이도와 분량을 고정할 수 있다.

1. 기본 튜토리얼에서 `플레이어 프렌드`와 `노프렌드`를 실제 선택 과제로 넣을지, 카드 프렌드 설명에서만 소개할지. 권장은 기본 과정에서는 카드 프렌드만 체험하고 나머지는 보조 카드로 안내하는 것이다.
2. 조커의 첫/마지막 트릭 예외까지 첫 튜토리얼에 넣을지. 권장은 본 과정에서는 조커가 강한 일반 트릭만 체험하고, 예외는 `특수 규칙 연습`에서 따로 다루는 것이다.
