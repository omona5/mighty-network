## 처리 결과 및 검증 근거 (2026-09-28)

- 팀 판정은 `Scoring.resolvedFriendId`로 통일했다. 공개 상태에 프렌드 ID를 전달하고 Unity도 닉네임 대신 ID로 프렌드 표시를 결정한다. 결과의 플레이어별 `role`로 점수 입력을 확인할 수 있다.
- 주공팀 점수는 주공 획득 점수 + 공개된 프렌드 획득 점수 + 버린 바닥패 점수다. 바닥패 점수는 기존 규칙대로 유지한다. 비주공 점수 혼입이라는 원래 증상은 재현되지 않았으므로 원인 해결이 입증됐다고 판단하지 않는다.
- 별도로, 잘못된 카드 요청이 직전 완료 트릭을 지우던 문제를 수정했다. 마지막 트릭 종료 여부는 손패 소진으로 확인하고 중복 종료 콜백은 무시한다.
- 일반 게임에서 30초 무입력 시 입찰 패스 / 바닥패 자동 선택 / 프렌드 자동 선언 / 합법 카드 자동 제출을 실행한다. 튜토리얼은 제외한다. 중복 예약·이전 턴·재배분·방 삭제 콜백을 차단하며, 자동 제출 후 손패도 재전송한다.
- 최초 입장과 게임 종료 후 복귀는 같은 대기실 UI를 사용한다. 모든 플레이어에 ○/●를 표시하고 내 버튼은 서버 `isReady`에 따라 `○ 준비` / `● 준비 취소`를 표시한다. 영어 버튼은 `Cancel Ready`다.
- 튜토리얼은 기존 `icon_etc`의 주공/프렌드 스프라이트를 TMP 인라인 글리프로 삽입한다. 글자와 함께 크기가 조정되고 줄바꿈된다. 텍스트 명칭도 유지한다.

## 추가 수정: 버린패 점수 공개 범위 (2026-09-29)

사용자 확인: 비주공 점수 혼입이 아니라 주공이 버린 점수 카드가 진행 중 팀 점수에 포함돼 보였던 현상이다. 위의 초기 조사 기록은 당시 결과이며, 최종 표시 규칙은 다음과 같다.

- **주공 본인**: 공개된 팀 획득 점수에 자신의 버린패 점수를 더한 합계를 표시하고, 버린패 점수가 1점 이상이면 `(버린패 n)`을 붙인다. 예: `주공팀 13점 (버린패 2)`.
- **프렌드와 수비팀**: 버린패 점수를 제외한 공개 획득 점수만 표시한다. 위 예시에서는 `주공팀 11점`이다. 서버도 이들에게 `kittyScore`를 전송하지 않으며, `pointsNeeded`도 공개 점수 기준으로 계산해 버린패 점수가 역산되지 않도록 한다.
- **프렌드 미공개**: 기존과 같이 공개된 팀원만 팀 획득 점수에 포함한다. 마이티 공개 여부를 별도 점수 분기 기준으로 사용하던 클라이언트 코드는 제거하고 서버 점수를 그대로 표시한다.
- **종료/정산**: 버린패를 합산한 실제 점수로 승패와 정산을 결정한다. 모두에게 최종 합계와 `버린패 n점 (주공팀 합계에 포함)`을 별도 줄로 공개한다. 버린패가 0점이어도 정산 화면에는 명시한다.
- **재접속·튜토리얼**: 서버의 수신자별 점수 계산을 동일하게 적용한다.

검증: `privateKittyScore.test.js`에서 주공/프렌드/수비팀/관전자, 0점 버린패, 교환 전 바닥패, 종료 시 승패 반전 및 영합 정산을 확인했다. 실제 5인 WebSocket 통합 테스트는 진행 중 각 수신자의 비공개 필드·합계·남은 점수와 최종 공개 결과를 검증한다. 전체 `npm test` 통과. Unity 실제 HUD 렌더링에서 `13점 (버린패 2)` / `11점` 및 텍스트 넘침 없음 확인.
