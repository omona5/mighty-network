## 목표

방마다 고유 URL을 부여해 초대 링크만 열면 해당 방 입장 화면으로 이동하게 한다.
로컬호스트에서도 동일한 흐름을 테스트하고, 추후 라즈베리 파이 운영 주소로 전환한다.

## 1. URL 및 화면 진입 규칙

- 멀티플레이 방 URL 형식: `/room/{roomCode}`
  - 예: `http://localhost:3000/room/ABCD`
  - 운영 예: `https://게임도메인/room/ABCD`
- 방 생성 성공 후 현재 화면을 해당 방 URL로 변경한다.
- 방 URL로 접속한 사용자는 **닉네임 입력 → 입장**만 표시한다. 방 코드는 URL에서 자동 사용한다.
- 일반 멀티플레이 로비에서는 방 만들기와 방 참여를 명확히 구분한다.
- 싱글플레이와 튜토리얼은 별도 URL/진입 경로를 사용하며, `/room/{roomCode}`에서 진입하거나 방 입장 상태로 전환되지 않게 한다.

## 2. 초대 링크 복사

- 대기실에 `초대 링크 복사` 버튼을 둔다.
- 현재 브라우저의 기준 주소 + `/room/{roomCode}`를 만들어 클립보드에 복사한다.
- 복사 성공/실패 안내 메시지를 표시한다.
- 로컬 테스트에서는 `localhost` 링크가 생성된다. 다른 기기에서 테스트할 때는 LAN IP, 터널 주소 또는 배포 도메인을 기준 주소로 사용한다.

## 3. 서버·클라이언트 구현 항목

### 서버

- 기존 `join_room` 요청의 방 코드 검증, 정원 확인, 게임 진행 중 입장 제한을 유지한다.
- URL은 클라이언트의 입장 편의 기능이며, 실제 입장 권한 검증은 항상 서버가 수행한다.
- 방이 없거나 종료되었거나 정원이 찬 경우 명확한 오류를 반환한다.

### Unity WebGL / 웹 셸

- WebGL을 제공하는 웹 페이지가 경로 기반 라우팅(`/room/ABCD`)을 처리하거나, Unity에 URL 경로를 전달한다.
- Unity 시작 시 URL에서 방 코드를 읽고, 멀티플레이 입장 화면을 초대 전용 모드로 연다.
- 방 생성/일반 참여 UI를 분리한다.
  - **방 만들기**: 닉네임 입력 후 생성
  - **방 참여**: 닉네임 + 방 코드 입력 후 참여
  - 방 코드 입력란에는 `참여할 방 코드를 입력하세요` 같은 안내 문구를 제공한다.
- 초대 전용 모드에서는 방 코드 입력란을 숨기거나 읽기 전용으로 보여 준다.

## 4. 토큰 적용 시 추가 구현 (선택)

방 코드만으로도 공개 방 초대는 가능하다. 비공개 초대, 링크 만료, 링크 유출 대응이 필요해지면 초대 토큰을 추가한다.

예시:

```text
/room/ABCD?invite={token}
```

- 방 생성 시 서버가 예측 불가능한 초대 토큰을 발급·저장한다.
- `join_room`에 `inviteToken`을 추가하고 서버에서 방 코드와 함께 검증한다.
- 토큰별 만료 시간, 사용 횟수 또는 폐기 기능을 관리한다.
- 방장이 `새 초대 링크 만들기` 또는 `초대 링크 무효화`를 할 수 있게 한다.
- 토큰은 로그·오류 메시지에 노출하지 않는다.

## 5. 로컬 테스트

1. `http://localhost:3000/room/{roomCode}`를 직접 열어 닉네임 입력 후 입장되는지 확인한다.
2. 방 생성 후 URL 변경과 초대 링크 복사를 확인한다.
3. 존재하지 않는 방, 정원 초과, 게임 진행 중 입장 오류를 확인한다.
4. 싱글플레이/튜토리얼 URL에서 방 입장이 실행되지 않는지 확인한다.
5. 토큰을 적용했다면 정상·누락·만료·폐기 토큰을 각각 확인한다.

## 6. 추후 Raspberry Pi 배포

- 라즈베리 파이에 WebGL 정적 파일과 Node.js WebSocket 서버를 배포한다.
- Nginx가 `/room/{roomCode}`를 포함한 클라이언트 경로에서 WebGL 시작 페이지를 반환하도록 설정한다. (새로고침 404 방지)
- HTTPS 및 `wss://`를 적용한다.
- 초대 링크의 기준 주소를 실제 도메인으로 전환한다.

## 7. 별도 버그 수정: 싱글플레이 나가기

- 검증 완료: Unity 컴파일 및 WebGL 빌드 성공(오류 0), 로컬 배포본 반영. 실제 브라우저에서 싱글플레이 게임 메뉴 → 방 나가기 → 타이틀(`/webgl/`), 이어서 멀티플레이 방 생성 → 방 나가기 → 로비(`/multiplayer`)를 확인. 브라우저 콘솔 오류 0건.
- 구현: `LeaveRoom()`에서 초기화 전에 `singlePlayerSession`을 보존하고, 공통 퇴장 정리 후 싱글플레이만 타이틀 씬을 로드한다. 싱글플레이 퇴장 URL은 `/webgl/`, 멀티플레이는 `/multiplayer`를 사용한다.
- 준비 단계가 끝나면 해제되는 `singlePlayerStarting` 대신 세션 전체에서 유지되는 `singlePlayerSession`을 사용해 게임 진행·결과·대기실 복귀 이후에도 같은 분기를 적용한다.

- 싱글플레이 중 `방 나가기`를 선택하면 멀티플레이 로비가 아닌 **타이틀 화면**으로 즉시 이동하게 수정한다.
- 멀티플레이의 `방 나가기` 동작은 기존처럼 서버 퇴장 처리 후 멀티플레이 로비로 돌아가는지 별도로 확인한다.

## 완료 기준

- 방 생성 후 각 방의 고유 URL로 이동한다.
- 초대 링크를 복사해 열면 해당 방의 닉네임 입력/입장 화면이 바로 열린다.
- 일반 멀티플레이 UI에서 방 만들기와 방 참여의 목적 및 입력 항목이 분명하다.
- 싱글플레이·튜토리얼은 방 URL로 진입할 수 없다.
- 싱글플레이에서 방 나가기를 선택하면 타이틀 화면으로 돌아간다.
- 로컬호스트에서 전 흐름을 검증한 뒤, Pi 배포 주소에서도 동일하게 동작한다.
